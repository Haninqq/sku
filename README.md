## 중요 전제 (프로젝트 도중 밝혀짐)

분석 대상 3편은 **서경대학교 정식 기출문제가 아니라 학원에서 만든 모의문제**다. 실제 서경대 기출 도면에는 **상수/하수 표기**와 **벽면 알파벳 라벨(A/B/C…)**이 있고 조건문이 그 알파벳을 직접 참조한다는데, 이 프로젝트가 가진 원본 3편에는 그게 없다. 실물 기출을 구할 수 없었기 때문에, 이 특징은 **검증 없이 규칙으로 확정**해서 앞으로 만드는 모든 도면에 반영하기로 했다 (`docs/출제_방정식_v1.html`의 02장·04장 참고). 나중에 실제 기출을 확보하면 이 부분을 재검토해야 한다.

## 핵심 원칙 요약 (전체 논리는 `docs/출제_방정식_v1.html` 참고)

1. **장면 우선 설계:** 조건 목록부터 쓰지 않는다. 완성도 있는 하나의 장면(분위기·긴장·하중 요소)을 먼저 확정한 뒤 조건을 추출한다.
2. **비중복 정보 분배:** 같은 정보(예: 오브제 위치)를 조건지와 도면에 동시에 중복해서 주지 않는다. 어느 채널로 보낼지는 장면마다 다르게 판단한다 — 고정된 항목-채널 매핑은 없다.
3. **고정 슬롯 vs 선택 슬롯:** 상수/하수 표기, 총괄 지시, 재질 구분, 색채 팔레트 등은 항상 있어야 하지만, 치수 조건·조명 지시·필수 입체 제작물·벽면 알파벳 라벨은 장면에 따라 있어도 없어도 된다.
4. **하중 조건 vs 교체 가능 조건:** "이 조건을 지우면 장면 정체성이 무너지는가?"로 판별한다. 하중 조건 3~4개를 먼저 확정하고 나머지를 그 주변에 붙인다.
5. **도면 = 전개도:** 도면의 모든 선분은 학생이 실제로 재단·채색해서 세우는 벽이다. 그려지지 않은 구간만 객석 쪽 개방부다.
6. 그림 실력은 설계 대상이 아니다. 완성도는 **분위기·의도 구현 > 조건 완성도 > 표현 기교** 순으로 판단한다.

## 이어서 작업할 때 (다른 세션/다른 사람을 위한 안내)

- 이 README + `docs/출제_방정식_v1.html`이 이 프로젝트의 **이식 가능한(portable) 전체 맥락**이다. 이 저장소를 클론하면 원본 자료와 결론이 다 들어있다.
- `docs/출제_방정식_v1.html`은 Claude 아티팩트로도 게시되어 있으며 이후 갱신될 수 있다 — 저장소의 사본이 최신이 아닐 수 있으니, 두 버전이 다르면 저장소 쪽을 기준으로 맞추거나 최신 아티팩트를 다시 받아온다.
- 이 대화를 진행한 Claude Code 세션의 "메모리" 파일(`~/.claude/projects/.../memory/`)은 **이 저장소에 포함되어 있지 않다** — 같은 사용자 계정의 같은 머신에서 새 세션을 열면 자동으로 남아있지만, 다른 머신/다른 계정의 세션이라면 이 README와 커밋된 파일들만이 유일한 근거가 된다.
- 다음 단계 후보: 실제 서경대 기출(상수/하수·알파벳 벽면 포함)을 구해서 "중요 전제" 항목을 검증하거나, `docs/출제_방정식_v1.html`의 12단계 절차를 따라 실제 새 모의문제 1편을 시험 삼아 제작해보는 것.
